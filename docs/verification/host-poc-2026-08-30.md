## Task 4 Silksong profile-routing regression

The existing Silksong path now resolves one selected `GameProfile` and carries
it through depot discovery/download, Unity staging, IL2CPP output, player-image
conversion and stamping, Addressables linking, reset, launcher handoff, and the
Unity shell. Mutable internal and external output is under
`profiles/silksong`; Unity, the compiler/toolchain, the user-selected source,
saves, and credentials remain outside generated-state adoption and reset.
Legacy adoption refuses to overwrite an existing profile tree.

Silksong's binary catalog reserves only 56 bytes for the absolute content
root, so the canonical `profiles/silksong/aa` path cannot fit with the package
name. The profile owns a unique compact runtime key and uses only
`files/p/ss/aa` for that link (52 bytes in the production package); all other
mutable state retains the canonical profile tree. Tests enforce the byte cap,
and catalog patch failure is now fatal rather than logged as a successful
rebuild. Adoption also records completion so a later reset cannot resurrect a
stale conflicting legacy tree, and an old app-downloaded depot is imported by
pointer without moving or rewriting its contents.
