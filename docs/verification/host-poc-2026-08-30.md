# Host POC Evidence — 2026-08-30

## Scope

This record covers Task 1 only: the host test runner, the existing Silksong
patch compile check, safe temporary-work handling, and the baseline
proprietary-content scan. It is not device, game-launch, or Milestone 1 closure
evidence.

## Robolectric runner

The pinned Unity Android module was fetched with its repository script into
`D:\Temp\dualsouls-unity-player`. The script verified the module's pinned MD5
before extraction. Gradle was invoked directly from that module because this
Windows host has no `make` executable:

```text
java -classpath D:\Temp\dualsouls-unity-player\android\Tools\gradle\lib\gradle-launcher-8.11.jar
  org.gradle.launcher.GradleMain -p src/SilksongLauncher.Launcher
  :app:testDebugUnitTest --no-daemon
```

Result: `BUILD SUCCESSFUL in 3m 55s`; 35 tasks executed. The test used
`RobolectricTestRunner` and loaded `R.string.launcher_app_name` through an
Android `Context`.

The build emitted pre-existing Kotlin nullability warnings in
`PackageCompiler.kt` and AGP's compile-SDK compatibility warning. Neither was
a test failure; they remain outside Task 1.

## Profile foundation

The profile and storage POC used test-first cycles. The red runs failed on the
expected missing symbols; the green run completed the full launcher host suite
successfully in 24 seconds.

- `GameProfilesTest` distinguishes current Hollow Knight 1.5.12620 from the
  1.5.12612 backward-compatibility reference, pins both Unity versions and
  content layouts, accepts only Linux, and fails closed on unknown IDs.
- `ProfilePathsTest` proves cross-profile isolation and rejects unregistered,
  traversal, absolute, and sibling-prefix identifiers using normalized paths.
- `SelectedGameStoreTest` proves the Silksong default, persistent Hollow Knight
  selection, unknown-value fallback, and rejection of unregistered profiles.

Commits: `d1a255d` (profiles) and `173243a` (paths/selection).
